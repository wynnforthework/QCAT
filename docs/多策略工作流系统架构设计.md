# 多策略工作流系统架构设计

## 系统概述

多策略工作流系统是从原有26项自动化功能闭环工作流系统中独立出来的第3-5层功能，专门负责策略的持续优化、进化和淘汰。该系统与单一全局工作流系统协同工作，形成完整的量化交易自动化体系。

## 核心组件设计

### 1. 策略工作流引擎 (StrategyWorkflowEngine)

负责单个策略的完整生命周期管理：

```go
type StrategyWorkflowEngine struct {
    // 策略标识
    StrategyID   string
    StrategyName string
    
    // 核心组件
    lifecycleManager *StrategyLifecycleManager
    backtestEngine   *BacktestEngine
    optimizerEngine  *OptimizerEngine
    learningEngine   *SelfLearningEngine
    
    // 资源管理
    resourcePool     *StrategyResourcePool
    concurrencyLimit int
    
    // 状态管理
    currentStage     StrategyStage
    activeJobs       map[string]*StrategyJob
    
    // 配置
    config *StrategyWorkflowConfig
}
```

**支持的生命周期阶段：**
- **引入阶段**: 策略代码生成、初始化配置
- **回测阶段**: 历史数据验证、性能评估
- **优化阶段**: 参数优化、多目标优化
- **自学习阶段**: 机器学习、策略进化
- **应用阶段**: 参数应用、性能监控
- **淘汰阶段**: 性能评估、策略淘汰

### 2. 多策略并发管理器 (MultiStrategyManager)

管理多个策略工作流的并发执行：

```go
type MultiStrategyManager struct {
    // 策略工作流实例
    strategyEngines map[string]*StrategyWorkflowEngine
    
    // 全局资源管理
    globalResourceManager *GlobalResourceManager
    globalScheduler        *GlobalScheduler
    
    // 并发控制
    maxConcurrentStrategies int
    maxConcurrentJobs       int
    
    // 策略池管理
    enabledStrategies  map[string]*EnabledStrategy
    disabledStrategies map[string]*DisabledStrategy
    
    // 事件系统
    eventBus *events.EventBus
}
```

### 3. 策略生命周期管理器 (StrategyLifecycleManager)

管理策略的状态转换和生命周期：

```go
type StrategyLifecycleManager struct {
    // 状态管理
    currentState StrategyState
    stateHistory []StateTransition
    
    // 性能跟踪
    performanceMetrics *PerformanceMetrics
    
    // 生命周期配置
    lifecycleConfig *LifecycleConfig
}

type StrategyState int
const (
    StateCreated StrategyState = iota
    StateBacktesting
    StateOptimizing
    StateLearning
    StateApplying
    StateEnabled
    StateDisabled
    StateArchived
)
```

### 4. 策略资源池 (StrategyResourcePool)

为每个策略分配独立的资源：

```go
type StrategyResourcePool struct {
    // CPU资源
    cpuQuota     float64
    cpuUsed      float64
    
    // 内存资源
    memoryQuota  int64
    memoryUsed   int64
    
    // 并发资源
    goroutinePool *concurrent.Pool
    
    // 数据资源
    dataConnections map[string]*DataConnection
    
    // 计算资源
    backtestWorkers  int
    optimizeWorkers  int
    learningWorkers  int
}
```

## 工作流程设计

### 策略生命周期流程

```
1. 策略引入 [功能8]
   ├── 策略代码生成
   ├── 初始配置设置
   └── 进入回测阶段

2. 策略回测 [功能19,20]
   ├── 历史数据回测
   ├── 性能指标计算
   ├── 风险评估
   └── 通过则进入优化阶段

3. 参数优化 [功能1,6]
   ├── 多目标优化
   ├── 参数空间搜索
   ├── 交叉验证
   └── 获得最优参数

4. 自学习进化 [功能24,25]
   ├── 机器学习训练
   ├── 策略结构优化
   ├── 自适应调整
   └── 生成新版本策略

5. 参数应用 [功能2]
   ├── 应用最优参数
   ├── 实时性能监控
   └── 准备启用

6. 策略淘汰 [功能7,10]
   ├── 性能评估
   ├── 淘汰决策
   ├── 启用/禁用策略
   └── 更新策略池
```

### 并发执行模式

#### 策略级并发
- 多个策略可以同时进行不同的生命周期阶段
- 每个策略有独立的资源配额
- 策略间互不干扰

#### 策略内并发
- 单个策略内可以并发执行多个任务
- 例如：同时进行多个参数优化实验
- 例如：并发执行多个回测任务

```
策略A: [引入] -> [回测1, 回测2, 回测3] -> [优化1, 优化2] -> [学习] -> [应用]
策略B: [优化1, 优化2, 优化3] -> [学习1, 学习2] -> [应用]
策略C: [回测] -> [优化] -> [学习] -> [应用]
```

## 与单一全局工作流的集成

### 策略池接口

```go
type StrategyPool interface {
    // 获取已启用策略
    GetEnabledStrategies() []*EnabledStrategy
    
    // 策略状态变更通知
    OnStrategyEnabled(strategyID string)
    OnStrategyDisabled(strategyID string)
    
    // 策略性能更新
    UpdateStrategyPerformance(strategyID string, metrics *PerformanceMetrics)
}
```

### 事件驱动集成

```go
// 多策略工作流系统发送的事件
type StrategyEvent struct {
    Type       StrategyEventType
    StrategyID string
    Data       interface{}

// 事件类型
const (
    EventStrategyEnabled  StrategyEventType = "strategy_enabled"
```
