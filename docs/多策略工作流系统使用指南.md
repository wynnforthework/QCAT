# 多策略工作流系统使用指南

## 系统概述

多策略工作流系统是从QCAT量化交易系统中独立出来的第3-5层功能，专门负责策略的持续优化、进化和淘汰。该系统与单一全局工作流系统协同工作，形成完整的量化交易自动化体系。

## 架构设计

### 系统分层

```
原有单一全局工作流架构 -> 新架构分离

多策略工作流系统 (独立系统):
├── 策略应用层    [2,7,10] - 参数应用、策略淘汰
├── 策略优化层    [1,6,24,25] - 参数优化、自学习
└── 策略管理层    [8,19,20] - 策略引入、回测

单一全局工作流系统 (交易执行):
├── 安全保障层    [14, 22] - 资金转移、交易所冗余
├── 收益优化层    [11]    - 利润最大化引擎
├── 交易执行层    [4,5,9] - 建仓平仓、止盈止损
├── 仓位管理层    [15,3,16,17] - 资金分配、仓位优化
├── [已启用策略池] - 来自多策略工作流系统
├── 监控分析层    [26,12,13] - 市场分析、风险监控
└── 基础数据层    [18,21,23] - 数据清洗、系统监控
```

### 核心组件

1. **多策略并发管理器 (MultiStrategyManager)**
   - 管理多个策略工作流的并发执行
   - 全局资源管理和调度
   - 策略启用/禁用决策

2. **策略工作流引擎 (StrategyWorkflowEngine)**
   - 单个策略的完整生命周期管理
   - 支持策略内部并发执行
   - 独立的资源池和状态管理

3. **进化管理器 (EvolutionManager)**
   - 策略进化和淘汰机制
   - 基因算法优化策略参数
   - 种群多样性维护

4. **交易策略池 (TradingStrategyPool)**
   - 已启用策略的管理
   - 与单一全局工作流的接口
   - 策略性能监控

5. **交易工作流引擎 (TradingWorkflowEngine)**
   - 专注于交易执行的工作流
   - 只处理已启用策略
   - 优化的交易执行路径

## 主要特性

### 🚀 多策略并发执行
- **策略级并发**: 多个策略可以同时进行不同的生命周期阶段
- **策略内并发**: 单个策略内可以并发执行多个任务
- **资源隔离**: 每个策略有独立的资源配额

### 🧬 智能进化机制
- **遗传算法**: 使用交叉、变异等操作优化策略
- **适应度评估**: 基于多维性能指标评估策略
- **自动淘汰**: 表现差的策略自动禁用

### ⚡ 高效资源管理
- **动态分配**: 根据策略需求动态分配CPU和内存
- **负载均衡**: 智能调度避免资源竞争
- **弹性扩展**: 支持资源池的动态扩缩容

### 📊 实时监控统计
- **系统级监控**: 整体运行状态和资源使用
- **策略级监控**: 每个策略的详细执行情况
- **性能分析**: 深入的性能指标和趋势分析

## 快速开始

### 1. 系统启动

```go
package main

import (
    "qcat/internal/strategy/workflow"
)

func main() {
    // 创建系统
    system, err := workflow.NewMultiStrategyWorkflowSystem(nil)
    if err != nil {
        panic(err)
    }

    // 启动系统
    if err := system.Start(); err != nil {
        panic(err)
    }
    defer system.Stop()

    // 系统现在正在运行...
}
```

### 2. 创建策略

```go
// 创建并运行策略
strategyID, err := system.CreateAndRunStrategy("我的策略", "momentum")
if err != nil {
    log.Printf("创建策略失败: %v", err)
    return
}

log.Printf("策略创建成功，ID: %s", strategyID)
```

### 3. 监控系统状态

```go
// 获取系统统计信息
stats := system.GetSystemStats()
fmt.Printf("活跃策略数: %d\n", stats.ActiveStrategies)
fmt.Printf("启用策略数: %d\n", stats.EnabledStrategies)
fmt.Printf("总执行次数: %d\n", stats.TotalExecutions)
```

## 配置说明

### 系统配置文件 (configs/multi_strategy_workflow.yaml)

```yaml
# 多策略管理器配置
multi_strategy_manager:
  max_concurrent_strategies: 10  # 最大并发策略数
  max_concurrent_jobs: 50        # 最大并发任务数
  global_cpu_quota: 20.0         # 全局CPU配额
  global_memory_quota: 42949672960  # 全局内存配额(40GB)

# 策略工作流配置
strategy_workflow:
  max_concurrent_jobs: 5         # 策略内最大并发任务数
  onboarding_timeout: "30m"      # 策略引入超时
  backtest_timeout: "60m"        # 回测超时
  optimization_timeout: "120m"   # 优化超时
  learning_timeout: "240m"       # 学习超时

# 进化管理器配置
evolution_manager:
  evaluation_interval: "30m"     # 评估间隔
  population_size: 20            # 种群大小
  mutation_rate: 0.1             # 变异率
  crossover_rate: 0.7            # 交叉率
```

## 工作流程

### 策略生命周期

```
1. 策略引入 [功能8]
   ├── 策略代码生成
   ├── 初始配置设置
   └── 进入回测阶段

2. 策略回测 [功能19,20]
   ├── 历史数据回测 (并发执行)
   ├── 性能指标计算
   ├── 风险评估
   └── 通过则进入优化阶段

3. 参数优化 [功能1,6]
   ├── 多目标优化 (并发执行)
   ├── 参数空间搜索
   ├── 交叉验证
   └── 获得最优参数

4. 自学习进化 [功能24,25]
   ├── 机器学习训练
   ├── 策略结构优化
   ├── 自适应调整
   └── 生成新版本策略

5. 参数应用 [功能2]
   ├── 应用最优参数
   ├── 实时性能监控
   └── 准备启用

6. 策略淘汰 [功能7,10]
   ├── 性能评估
   ├── 淘汰决策
   ├── 启用/禁用策略
   └── 更新策略池
```

### 并发执行模式

```
策略A: [引入] -> [回测1,回测2,回测3] -> [优化1,优化2] -> [学习] -> [应用]
策略B: [优化1,优化2,优化3] -> [学习1,学习2] -> [应用]
策略C: [回测] -> [优化] -> [学习] -> [应用]
```

## 性能优化

### 资源配置建议

- **CPU配额**: 每个策略建议分配1-2个CPU核心
- **内存配额**: 每个策略建议分配2-4GB内存
- **并发数**: 根据硬件配置调整最大并发策略数

### 监控指标

- **系统级**: CPU使用率、内存使用率、活跃策略数
- **策略级**: 执行时间、成功率、资源消耗
- **业务级**: 策略性能、收益指标、风险指标

## 故障排除

### 常见问题

1. **策略创建失败**
   - 检查资源配额是否充足
   - 确认并发限制设置
   - 查看错误日志

2. **系统性能下降**
   - 监控资源使用情况
   - 调整并发参数
   - 优化策略算法

3. **策略执行超时**
   - 增加超时时间配置
   - 优化策略逻辑
   - 检查数据源连接

### 日志分析

系统日志位置: `logs/multi_strategy_workflow.log`

关键日志关键词:
- `ERROR`: 系统错误
- `WARNING`: 警告信息
- `策略`: 策略相关操作
- `资源`: 资源分配相关
